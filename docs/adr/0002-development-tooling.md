# 0002. Development tooling for the monorepo

- Status: Accepted
- Date: 2026-10-06 (decisions made during the bootstrap, 2026-10-04 to 2026-10-06)

## Context

The bootstrap needs a working TypeScript monorepo before any product code exists. The constraints:

- There is one developer, and many changes are written by an AI assistant, so the guardrails have to be automatic, not remembered.
- The repo is public, so secrets must never reach a commit.
- `packages/core` must stay portable to future browser and React Native clients.
- Operations should stay boring and cheap.

Versions were checked against the npm registry, nvm and the GitHub API on 2026-10-04.

This ADR covers development tooling only. The runtime stack (HTTP framework, database access, time library, LLM orchestration) is decided in the slice that first needs it (slice 1).

## Consequences

- **Upgrade watchlist:** TypeScript 7 (when typescript-eslint supports it) and pnpm 12 (when global installs move to it). Each upgrade is a new ADR, or a note superseding this one.
- **No in-editor boundary warnings:** violations surface at pre-push and in CI.
- **Hook speed:** about 3 s for pre-commit today. The lefthook job timeouts (120–180 s) turn a hung run into a failure instead of a stall.
- **Setup steps:** contributors need `nvm` (or Node 24 on PATH) and `pnpm install`. The README documents this.
